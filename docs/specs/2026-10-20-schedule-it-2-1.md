# Schedule-it 2.1.0

> **Status:** built - **Version:** 0.2
> A long job no longer holds back the other jobs due with it, a job can run as its own process,
> a shell command can sit in the schedule beside the console commands, and `schedule-it/list`
> shows what an operator needs to run a job by hand and when it runs in the site's own time.

---

## 1. How it works

`schedule-it/run` works out which jobs are due this minute, from their expressions and any
`when()` / `skip()` filters, without taking any lock. It then takes the jobs in order. For each
one it takes that job's lock, checks the job has not already been started for this minute or a
later one, runs it, and releases the lock as soon as it ends. A job whose lock is held is
reported as skipped and the runner moves on to the next.

A job marked `->background()` is not run by the runner. The runner starts a separate process,
`schedule-it/run/job <id> <minute>`, which takes the lock, runs the job and releases the lock
exactly as the runner would, writing everything to the log file. The runner moves on at once.

`Job::exec('<shell line>')` is a job that runs a shell command from the project root, with the
same lock, log capture and replay as a console command.

`schedule-it/list` shows each job's description with the command beneath it, and its next run
both in the job's timezone and in Craft's.

## 2. Scope

**In:** issue #1 (per-job lock, `->background()`); issue #2 parts 1 and 3 (command in `list`,
`Job::exec()`); the Craft-timezone column in `list` that answers #2 part 2.

**Out:** changing the default timezone from UTC (#2 part 2, kept by Sam's decision of 20 Oct
2026: a UTC schedule does not move twice a year). Locks for closures added with the library's
`call()`. Any database table. Commenting on or closing the GitHub issues.

## 3. User journeys

1. A site schedules a 10-minute import every five minutes and `gc/run` every minute. The
   import's runner keeps running; each later minute's runner skips the import as still running
   and runs `gc/run` on time.
2. The same site marks the import `->background()`. The runner starts it and runs `gc/run` in
   the same minute without waiting.
3. A site adds `Job::exec('bin/geoip-update.sh')->weekly()`, removing its own crontab line.
4. An operator in Zagreb runs `schedule-it/list` and sees a `dailyAt('07:00')` job is next due
   at 09:00 Europe/Zagreb, with `craft reports/send` beneath its description to copy.

## 4. Data model

No tables. One cache entry per job in Craft's `cache` component: key
`schedule-it/started/<id>`, value the UTC minute it was last started (`YmdHi`), kept a day.

A job's **id** is the first 12 hex characters of `sha1(<cron expression> + ' ' + <route or shell line>)`.
It names the lock (`schedule-it/<id>`) and the cache entry, and is what a background process is
given. It contains no path, so every server derives the same one.

## 5. Rules

- **BR-1** Working out which jobs are due takes no lock. A job's lock is taken immediately
  before it runs and released immediately after, whether it succeeded, failed or threw.
- **BR-2** A job whose lock is held is skipped and reported as still running; the runner carries
  on with the next job. A skip is not a failure and does not change the exit code.
- **BR-3** With the lock held, a job already started for this run's minute, or a later one, is
  skipped and reported as already started. Otherwise its start minute is recorded before it
  runs. This is what stops a second runner in the same minute repeating a job the first has
  finished. It is only as shared as Craft's cache: a file cache covers one server.
- **BR-4** Every job's due-ness is read against one moment, taken when the runner starts.
- **BR-5** The library's `withoutOverlapping()` and `onOneServer()` change nothing on a
  schedule-it job (every job is already locked by BR-1), so calling them in `configure` cannot
  bring back the up-front lock. A `skip()` added in `configure` no longer replaces the lock.
- **BR-6** `->background()` (or `'background' => true`) starts the job as its own process and
  does not wait. That process obeys BR-1 to BR-3, appends the job's output and its own result
  line to the log file, and exits with the job's exit code. The runner reports the process id.
  Its output is not replayed to the runner's stdout.
- **BR-7** `Job::exec('<line>')`, or a list entry with `exec` in place of `command`, runs the
  line through the shell from the project root, wrapped so a redirect covers all of it
  (`a && b` logs both). It has the same lock, log, replay and exit-code report as a console job.
- **BR-8** `exec` is refused with `command`, as the key of a keyed entry, or empty;
  `background` is refused unless it is a bool or an env var that reads as one. As before, a
  mistake is reported by `run` and `list` only, never on a web request.
- **BR-9** `list` shows the command beneath a job whose description differs from it: `craft
  <route>` for a console job, the line itself for a shell job.
- **BR-10** `list` shows each job's next run in the job's timezone and in Craft's timezone, and
  whether it runs in turn or in the background. The default timezone stays UTC.
- **BR-11** A job's output is read from its own process as it is written, appended to the log
  file and echoed to the runner's stdout. A runner never echoes another runner's output from
  the shared log. Output a job was pointed at itself (`sendOutputTo()`, `appendOutputTo()`)
  stays where it was sent.

## B2. Context to load

1. `vendor/omnilight/yii2-scheduling/src/Event.php` — `withoutOverlapping()` (533) puts the
   lock in the `skip()` filter, which `isDue()` calls; `skip()` replaces any earlier filter.

3. `vendor/craftcms/cms/src/helpers/Console.php` — `table()` (239): no multi-line cells,
   `maxSize` truncates.

## B3. Guardrails

- **Do not take any lock in a filter** — that is the bug.
- **Do not hold a lock through a process the runner does not wait for** — a MySQL lock dies
  with its connection; the background process takes its own.
- **Do not let a `Job` method throw** — the config file loads on every web request.
- **Do not change the default timezone.**
